# GNS3 Web UI 拓扑标注布局算法

> 把"给拓扑画布摆标注"抽象为一套可复用的算法：**几何原语 + 优先级贪心消解引擎 + GNS3 适配**。
> 全部结论来自 vxlan-compute-test 项目上的逐项实测（2026-10-16）。

## 文件构成

| 文件 | 角色 |
|---|---|
| `gns3_label_layout.py` | 通用库：几何原语 / 消解引擎 / 风格工具 / GNS3 适配（零依赖，与项目无关） |
| `place_link_labels.py` | 项目 CLI：实体映射与风格配置 + 调库出计划 + 与线上 diff |
| `GNS3-标注布局算法.md` | 本文档 |

## 一、坐标系与锚点（实测定案，勿再猜）

- 画布 = **左手笛卡尔坐标系**：x 右正、y 下正、原点在场景中心
- **节点 (x, y) = 图标左上角**；图标 60×60 → 图标体 `(x,y)~(x+60,y+60)`、图标中心 `(x+30, y+30)`
- **drawing (x, y) = 左上角**（渲染时按左上角摆放，非中心点）
- **link 几何 = 两端"图标中心"的直线段**（不是节点坐标点连线）
- **text 尺寸**：宽 = 最长行字符数 × font_size × 0.8；行高 = round(font_size × 1.9)
  （font 10/12/14 → 行高 19/23/27）

> 两个换算方向相反：节点锚点→图标中心是 **+30**；形状中心→左上角是 **−半宽高**。

## 二、碰撞模型

- **框×框**：AABB，两框间隙 < pad 视为碰撞（pad 默认 6px）
- **框×线段**：矩形（**含高度**）与线段的最近距离 < pad 视为碰撞；相交时距离=0
  - 判定必须用整个矩形（四角+边）对线段取最小距离
  - **斜线的关键接触点是底边角**——斜线向下扫，左上角净空 ≠ 底角净空

## 三、理想位置规则（项目风格层）

| 实体 | 理想位置 |
|---|---|
| 斜线 mesh 标注 | 链路 ∩ 中部带（FRR 质心 y + 5.5）交点，左起 min-gap 200 推挤防叠 |
| 水平 mesh 标注 | 坐标中点 + (17.5, 5.5) |
| 接入横线标注 | 坐标中点 + (30, 5.5) |
| 接入竖线标注 | 坐标中点 + (80, 17.5)（右侧悬挂） |
| 节点对形状 | 两图标体并集四周**对称**外扩 45 → 形状中心严格重合节点组中心 |
| 区域标签 | 形状上方 caption（左缘+8、底边距形状顶 8） |
| 标题 | 固定位（作为障碍参与消解） |

> 偏移量是用户手调布局反推的**经验公式**——复现既定审美；实际净空由消解层保证。

## 四、消解引擎（贪心最小位移，确定性）

实体模型（`Entity`）：

```
mode:
  fixed       — 固定不检，自身作为障碍（标题）
  candidates  — 候选槽位按序扫描，首个"全净"即选；全脏 → 最少碰撞槽位+fallback 标记
                （区域标签：caption 上/下 ±平移扫描 → 四内角 → 远程平移）
  slide-x/-y  — 沿保语义轴双向扫描（0, +step, -step, +2step, ... 首个全净即选）
                （斜线/水平标注→x，竖直接入→y；步长 4、上限 300）
```

流程：按 **priority 降序**逐个摆放（先到先占）；每个实体避开 `障碍框 + 线段 + 已放实体`；
扫描上限内无解 → `unresolved` 标记（不静默）。全部摆完后 `audit()` 全对全复核。

**优先级**（本项目）：标题(100) > 区域标签(10) > 链路标注(5)。
**无自身豁免**：文字一律避让所有线段（含自己那条）。

## 五、CLI 用法

```bash
# ① 现拉节点坐标(MCP node_list 带 x,y) → nodes.json
# ② 计算计划 + 碰撞复核
python3 place_link_labels.py nodes.json

# ③ 与线上画布 diff(先拉 MCP drawing_list 存 drawings.json)
python3 place_link_labels.py nodes.json --current drawings.json
#   → 只列出需更新的项: # !! [tag ...] abc12345 (旧) -> (新)
```

参数：`--pad 6`（最小间隙）、`--min-gap 200`（斜线带防叠间隔）。

**工作流纪律**：每次取最新坐标（坐标会被人从 web ui 移动，任何缓存都会过期）；
计算→执行→独立复核；执行按 `drawing_update` 速查逐条 MCP 下发。

## 六、扩展点与边界

- link 含折点/曲线 → 把线段原语替换为折线最小距离，引擎与 mode 不变
- 新实体类型（图标/自由注释）→ 增加 mode 分支
- 换渲染平台/锚点语义变化 → 只改 `§4 GNS3 适配` 函数
- 诚实边界：link=直线是当前假设；greedy 非全局最优，但对几十个标注足够且确定可解释

## 七、踩坑纪要（结论背后的教训）

1. **锚点语义**：节点是左上角语义（非中心），曾按中心计算 → 整体偏左 60-120px、上半个空
2. **text 尺寸**：曾用估算宽 80（实际 96），低估 16px 使间隙缩水成"贴线"
3. **link 端点是图标中心**：曾用节点坐标点连线——"0.0px 骑线验证"是循环论证；
   底角重叠现象+手调坐标复核（10 条中 7 条会穿字 vs 9/10 自然净空）双双证伪
4. **必须含高度的判据**：只比坐标级 x 距离会漏掉"底边角被斜线切中"
5. **工作流**：心算/缓存坐标两次翻车；脚本计算 + MCP 执行 + 独立复核是纪律

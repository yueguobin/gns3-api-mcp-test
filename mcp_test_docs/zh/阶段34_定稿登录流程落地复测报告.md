## 2. 未通过项（L1–L5）

### L1（核心）console_login 确认逻辑自相矛盾——探测成功仍报未确认

三次调用、三种会话状态，tail 全部含**成功探测**（nonce marker + uid/user），但 `login_confirmed` 全为 false；`already_shell=true` 从未出现：

| 调用 | 会话状态 | reason | tail 关键行 |
|---|---|---|---|
| UDG-1（docker，无凭据） | bash 活 | credentials_missing | `0\nroot\n__MCP_DONE_3fb9809a_0__` |
| CG-1（QEMU，有凭据）① | shell 活（前次调用已登入） | login_unconfirmed | `…\n1000\nubuntu\n__MCP_DONE_eb7e7ffe_0__` |
| CG-1 ②close 后 | 登出→自动登录复活 | login_unconfirmed | `…\n1000\nubuntu\n__MCP_DONE_93159f4f_0__` |
| CG-1 ③忙清除后 | shell 活 | login_unconfirmed | `…\n1000\nubuntu\n__MCP_DONE_ca40510a_0__` |

判定依据：tail 中 nonce+数字 exit 的 marker 只可能由真 shell 执行探测产生（getty 回显不会展开 `$?` 成数字）。**探测结果没有被确认逻辑采纳**。推断（未证实）：确认器在匹配字面 `__MCP_DONE_<nonce>_$?__` 而非展开后的数字形式。附带：UDG-1 场景 probe 成功仍走凭据检查报 credentials_missing，与定稿"已有 shell 直接 already_shell、凭据零写入"相悖。

### L2 探测先行被违反：凭据盲发进活 shell，密码明文落 console

CG-1 三次（①③）调用时 shell 已活（tail 中 `__MCP_PROMPT__` PS1 锚点在场），console_login 仍执行 blind_login：`^C` 清理 + 用户名/密码逐条写入——被 bash 当命令执行：

```
__MCP_PROMPT__ ubuntu
ubuntu: command not found      ← 用户名
__MCP_PROMPT__ ubuntu
ubuntu: command not found      ← 密码（密码=ubuntu，明文出现在 console transcript）
```

**密码以明文出现在 console 输出流**——"密码不回传"仅指 MCP 响应，被此路径旁路。按定稿，探测先行命中 shell 时根本不该发凭据。

### L3 exec 路径的 F4 恢复仍不可靠（探测先行未见生效）

| 轮 | 序列 | 结果 |
|---|---|---|
| 一 | 登出→A 写前(4s 不读) exec | timeout 20s，输出无探测/命令回显 |
| 一 | B（Password: 态）exec | timeout 20s，探测文本被当密码 `Login incorrect` |
| 一 | C（不 close 重试） | **ok**（提示符+命令，无 MOTD——复用已恢复 shell） |
| 二 | 登出→E1→E2 | **双双 timeout 20s** |

C 偶发成功的机制不明（可能是 B 超时后的异步恢复迟到落位）；输出中**始终看不到探测命令的回显**，说明 exec 写前探测没有发生（或未到达 console）。结论：登出后 exec 自动恢复**不生效/不可复现**，与前版行为实质相同。

### L4 无凭据+登出态 exec 无快速失败

CG-1 清凭据、console 处于 login: 时 exec：20s timeout，输出 `Login incorrect\nubuntu-cloud login: `（命令被当用户名）。设计的 credentials_missing 快速失败只在 console_login 的新会话路径生效，exec 缓存会话路径没有。

### L5 节点重启后 console_login 复用死连接

CG-1 stop→start 后连续两次 `Console login failed: Socket is closed`；console_close 一次即愈。会话缓存未感知节点重启（console host/port 未变，身份比对不触发——与 92bc5f2dd 已知盲区同类）。

## 3. 环境限制（非服务端问题）

- 本 harness 的 console_send 只能发字面 `\u0003`/`\r` 字符串（sent 回执可证），**真 Ctrl-C 中断路径不可测**；忙清除仅验证了迟到 marker 正路。
- 空 read 不清忙状态为设计行为（需 marker 或 \x03），实测一致。

## 4. 统计与修复建议优先级

- 通过 7 项 / 未通过 5 项（L1–L5）/ 环境限制 2 项
- 优先级：**L1（确认逻辑，console_login 全场景误报+连带 L2 凭据盲发）＞ L3（exec F4 恢复，核心验收目标）＞ L2（密码明文落 transcript，随 L1 修复）＞ L4/L5**
- L1 修复后复测点：三种会话状态各一次 console_login（期待 already_shell=true / 盲发登录成功 / credentials_missing），并确认活 shell 时零凭据写入（tail 无 `command not found` 痕迹）

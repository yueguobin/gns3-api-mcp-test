**③ TLS 配置**（自签证书，SAN 覆盖域名+IP；证书存持久卷；olcTLS* 挂 `cn=config` 全局条目，配置见 `labs/openldap26-tls-config.ldif`）：

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout server.key -out server.crt -subj "/CN=192.168.101.31" \
  -addext "subjectAltName=DNS:localhost,DNS:ldap.example.org,IP:192.168.101.31"

docker exec GNS3.OpenLDAP-1.<project-id> mkdir -p /var/lib/openldap/openldap-data/tls
docker cp server.crt GNS3.OpenLDAP-1.<project-id>:/var/lib/openldap/openldap-data/tls/
docker cp server.key GNS3.OpenLDAP-1.<project-id>:/var/lib/openldap/openldap-data/tls/
docker exec GNS3.OpenLDAP-1.<project-id> sh -c \
  'chown 911:911 /var/lib/openldap/openldap-data/tls/*; chmod 600 /var/lib/openldap/openldap-data/tls/server.key'

ldapmodify -x -H ldap://192.168.101.31:3890 -D "cn=admin,cn=config" -w config \
           -f labs/openldap26-tls-config.ldif
```

注意两条操作规则：olcTLS* 必须挂在 `cn=config` 全局条目（挂 frontend 库条目报 error 65）；属性已存在时把 `add:` 换 `replace:`（重复 add 报 error 20）。

### 5.3 关键行为记录（测试 29 / 31）

**测试29 refresh × 撤销**（完整时序）：

```text
1) carol 登录 200，存 access_token + refresh_token
2) 撤销前 access_token 打 /v3/access/users → 200（Administrators 角色）
3) 目录侧移除 carol 的 gns3-admins + gns3-testers member
4) 撤销后旧 access_token → 200（fail-open：已发 token 不重查目录）
5) 撤销后新登录 → Users 回退，access_token 探测 403
6) POST /v3/access/users/refresh {"refresh_token":…} → 200，签发新 access_token
   → 新 access_token 探测 → 403（刷新时按目录现状重算角色！）
7) 成员恢复 → 新登录 200、探测 200
```

功能语义：已发 access_token 在目录变更后仍用到过期（fail-open），但**任何一次 refresh 都会重算**——会话角色收敛点是 refresh，不是登录。

**测试31 ppolicy 锁定**（本环境配方：镜像自带 `cn={4}ppolicy` schema，无需导入；模块 `ppolicy.so` 加载 + 挂 `olcOverlay=ppolicy` 到 `{1}mdb` + 建策略条目（`organizationalRole` 结构类 + `pwdPolicy` 辅助类，pwdLockout=TRUE/pwdMaxFailure=3/pwdLockoutDuration=60）+ 用户条目挂 `pwdPolicySubentry` 指向策略）：

```text
3 次错密码 → 401×3
第 4 次=正确密码 → 401（目录级锁定生效；限速器阈值是 5 次，此 401 先于 429 出现）
等 61s（pwdLockoutDuration=60）→ 正确密码 → 200（自动解锁，成功 bind 重置失败计数）
```

功能语义：目录侧密码策略与 GNS3 限速器是**两层独立保护**——锁定让"正确密码也 401"，且先于限速器触发；过期自动解锁无需人工干预。
